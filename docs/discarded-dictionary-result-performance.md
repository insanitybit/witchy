# Discarded dictionary result performance

Dictionary insertions whose results are discarded need not allocate the displaced-value `Option`. The lowerer recognizes checked wrappers that forward a local mutable dictionary and their ordinary key/value parameters exactly once to `dict.__insert_value_extract`. In effect position, it performs the existing checked table update without constructing that result. Used results, indirect calls, other wrapper bodies, and affine key/value carriers keep their existing path. The optimization is gated by `DirectCall`.

On October 9, 2026, a paired ARM64 macOS release measurement of `dict_count` on base `9f2c21d67` improved from 32.9 ms to 20.9 ms: 1.58× faster, with a paired bootstrap 95% interval of 1.43–1.76×. Three counted runs per binary each reported allocations falling from 3,000,018 to 18 and releases falling from 3,000,025 to 25. Timings used uninstrumented binaries, two warmups, and twelve AB/BA pairs. Both binaries produced the independently checked result, and counted admission preflights reported no canonical fallback.

Records, lists, trees, and closure calls retained identical allocation and reference-count counts; their timing differences were inconclusive. Counters cover complete guest execution in linear memory, including output preparation, and do not count host or Wasm GC allocations. Main-thread CPU sampling of the original dictionary kernel attributed about 58% of guest self samples to the insert function; that includes lookup and update work, not just allocation.

All 71 native codegen tests passed before and after rebasing onto master `608c0574b`; the post-rebase run completed in 16.19 seconds. Focused coverage checks the caller rewrite through SafeWIR admission and exercises snapshots with structured String values, argument evaluation order, used insertion results, wrappers with additional work, and complete linear-heap cleanup with optimizations disabled, `DirectCall` disabled, and all optimizations enabled.

Raw binary/source fingerprints, repeated counters, paired timing samples, validated outputs, and JIT profiles are retained under `state/agents/general-runtime-hotspots-20261009/`, especially `discarded-insert-candidate/source.json` and `discarded-insert-paired/results.json`. This general optimization is independent of the held async transport experiment.
