witchy glamour — real-browser demo

Two footprint-empty witchy runes, compiled to WASM, running under the deny-all pure-compute host (RFC-0007) and the glamour DOM shell (RFC-0008). The runes compute; this page holds all the authority and acts.

1. Counter (MVU: render → click → update → re-render)

The +/- buttons dispatch a Msg into the rune; the new VNode is diffed into the DOM. No innerHTML anywhere.

2. Highlighter (pure render; <script> stays inert text)

The source below includes a comment, a string, and a literal <script>. The rune routes every token through a text(...) node, so the script tag renders as four inert characters — never a real element.

3. Rune cards (coven's capability footprint, rendered by a witchy rune)

witchy's OWN capability-footprint model, displayed by a footprint-empty witchy rune. Each registry record (name, version, declared caps, provenance) becomes a card: a red badge per capability, or a green cap-none badge for the celebrated empty footprint. The last record's name is a literal <script> — it routes through a text(...) node, so it renders as inert text, never a real element.

4. Coven browser (capstone MVU app: a navigable multi-view UI)

One footprint-empty witchy rune that is a whole application: an INDEX of clickable rune cards, and a DETAIL view (the card + its syntax-highlighted source + a ← back button). A click dispatches a Show(i)/Back Msg into the rune; update folds it and the new VNode is diffed into the DOM. The evil/inject rune's source carries a literal <script> — it routes through a text(...) node, so it renders as inert text, never a real element. The full MVU navigation loop, end to end, in the browser.
