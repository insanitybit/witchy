# RFC-0165 base64 encoder review

Scope: `c010a17b3..579975a92`, base64 encoder and its real-stdlib probe only.
Read-only; no build or test run.

## Finding

### Medium: output-length multiplication can wrap after the input guard

`lower_base64_encode` admits every input through `u32::MAX - 6`, which proves
only that `total + 2` is representable.  It then computes
`4 * ((total + 2) / 3)` with `OverflowBehavior::Wrap` and checks the already
wrapped result against the allocation maximum
([canonical_lower.rs:8093-8106](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8093)).

For example, `total = 3,221,225,470` passes the first guard, but produces
`groups = 1,073,741,824`; multiplying by four wraps the 32-bit `Size` to zero.
The second comparison accepts zero, so the encoder allocates a zero-length
output and enters its nonempty input loop.  The first output store then fails
its capacity guard ([canonical_lower.rs:8166-8175](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8166), [canonical_lower.rs:8502-8517](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8502)).

This is not a demonstrated memory-safety escape: every byte store retains a
capacity bounds guard and traps.  It is nevertheless an incorrect overflow
admission condition: a representable source String can reach a wrapped output
extent instead of trapping before allocation.  The encoder needs a pre-multiply
bound equivalent to `4 * ceil(total / 3) <= u32::MAX - 4`, rather than only a
bound on `total + 2`.

## Checked portions

- The group loop requires `input < total` before loading byte zero; optional
  byte loads branch on their own `index < total` and use zero on the absent
  edge ([canonical_lower.rs:8125-8136](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8125), [canonical_lower.rs:8381-8404](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8381)).
  Thus one- and two-byte tails form the required zero-filled 24-bit group;
  `c2` and `c3` are independently replaced with `=` when byte one or two is
  absent ([canonical_lower.rs:8161-8165](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8161)).
- The six-bit masks constrain alphabet indices.  The selection boundaries are
  `0..25 -> A-Z`, `26..51 -> a-z`, `52..61 -> 0-9`, `62 -> +`, and `63 -> /`
  for this standard (non-URL) entry point
  ([canonical_lower.rs:8146-8160](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8146), [canonical_lower.rs:8310-8335](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8310)).
- Output is a fresh counted reference object, all successful stores are
  checked scalar byte stores, and the source is only loaded.  This slice shows
  no ownership alias or drop discrepancy ([canonical_lower.rs:8407-8426](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/crates/witchy-lower/src/canonical_lower.rs:8407)).
- The probe is credible for ordinary behavior: it uses the real `encoding`
  module, pins external expected vectors for lengths 0 through 4 and UTF-8,
  compares source interpreter output with the canonical interpreter and Wasm,
  and checks canonical heap leaks ([rfc0165_encoding.rs:75-109](/Users/cobrien/workspace/witchy/.codex/worktrees/rfc0165-encoding-next/tests/misc/rfc0165_encoding.rs:75)).
  The canonical interpreter and Wasm are deliberately two executions of the
  same admitted artifact, so their agreement is backend parity evidence; the
  source interpreter plus literal vectors supplies the independent semantic
  oracle for this probe.

## Author disposition

This section is author evidence for correction commit `f712395e9`, not an
independent reviewer re-review of that correction.

The correction replaces the unsafe `total + 2` representability bound with a
pre-multiply bound.  The exact permitted source total is `3_221_225_466`:
`ceil(total / 3) * 4 = 4_294_967_288`, within the `u32::MAX - 4` output limit.
The reviewed boundary `3_221_225_470` requires `4_294_967_296` output bytes and
is rejected before output-size multiplication and allocation.
