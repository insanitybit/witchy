# Fixed proof import closure

The compiler's generated Lean module imports the fixed elaboration, tactic and
auditor roots listed in the private `IMPORTS` constant in `src/compiler/proof.rs`.
The ignored real-audit test helper uses the same constant. This removes the broad
`import Lean` umbrella while retaining the fixed supported proof language.
It does not establish a mathematically minimal transitive import closure.

The roots cover ordinary commands/terms/declarations, custom tactic elaboration,
`#eval` of the unchanged CoreM auditor, structure instances, arithmetic Omega,
case splitting, simplification/unfolding, axiom collection and Init.Omega.
The inline core omega wrapper remains: the stock frontend hides proofs in
auxiliary theorems that would violate the existing closed theorem inventory.

Every generated byte after the import header is unchanged. Authored source and
model meanings, all selected expected statements, goal inventories, prover
scripts, options, kernel trust, theorem/axiom auditing and output protocol remain
unchanged. Reduced imports can still change registered elaborators or the default
simp set. Qualification must check functional eligibility; contracts and auditing
must never be weakened to compensate for a missing import.

The complete trusted SDK remains the identity scope. Both complete installation
snapshots and compiler-file hashes still run around the existing fresh proof
operation. There is no import-based SDK pruning, receipt/admission reuse,
resident checker, skipped currentness check or SDK installation change. The
zero-goal path still returns before import construction and tool configuration.
Import-header changes legitimately change generated-module/request identities;
compiler bytes naturally receive a new compiler identity. Source/model/audit
identities and expected statements should retain parity on matched inputs.

The prior startup diagnostic used three interleaved audited trivial runs per
variant: full-import child median 1.677s versus reduced-import 0.941s. Its
unchanged auditor accepted version, trust, expected type and closed axioms. That
is a child-only diagnostic, not a complete compiler speedup or proof-language
qualification. Whole-child time includes startup/import loading, elaboration,
tactics, kernel checks, audit and scheduling effects; it is not kernel-only.
The separately qualified ordered-read-ahead improvement remains distinct.

Focused qualification passed: an actual four-layout Vec proof, then one frozen
affected matrix covering ghost/scalar/U64/Init/record/caller/mixed proofs and
strict audit negatives. Optimized qualification retained exact expected
statements, source/model/audit/SDK identities and emitted Wasm; generated Lean
module identity changed as intended. False unused proofs still refuse before
publication and preserve existing output. No historical full gate was required.

Twelve interleaved matched Vec code-edit pairs comparing read-ahead/full imports
with read-ahead/reduced imports measured paired elapsed ratio 0.87634 (95%
bootstrap interval 0.85875–0.90587): 12.4% lower time on that workload. Medians
were 4.6914 s and 4.1143 s. Whole-child medians fell from 1.8547 s to 1.2727 s;
full installation A+B medians were 2.8409 s and 2.8039 s. The proof-free control
showed no resolved change. The import-only authored-proof-edit comparison was
inconclusive (ratio interval 0.85579–1.03984), so it is not an incremental proof
speedup claim.

A separate direct original-to-final comparison of both retained improvements
measured 12 authored Vec proof-edit pairs: paired ratio 0.63736 (95% interval
0.60588–0.67811), or 36.3% lower elapsed; all 12 were faster. Those edits strengthen
an actual verified postcondition while preserving runtime bytes/output. This is
a direct result, not multiplication of intervals from separate experiments.
These are finite-sample same-host results for the bounded two-goal/four-layout
client, not cold-filesystem, full Vec functional proof, old native workload,
RSS, kernel-only or universal optimality claims. See [performance evidence](wasm-performance.md)
for input boundaries, qualification and the preserved outer-driver bookkeeping
failure in the direct proof-edit campaign.
