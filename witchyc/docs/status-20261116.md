# Status, 2026-11-16

Branch `work/vec-string-core`. Every claim here has a fixture or unit test named in the
linked docs; the whole fixture set (every fixture with an expectation, 487 programs, run
in Wasmtime) and 255 unit tests pass at `992bc3cb`.

## What works

**Containers.** `Vec<T>` and `String` built on `Buffer<T>`, with every unchecked
memory operation inside a function whose contract Lean checks (docs/wasm-vec-growth.md,
docs/wasm-string.md). `HashMap`, `Deque`, `Option`, JSON, HTTP (docs/wasm-http.md), sorting and formatting
are libraries over them. Records may hold several allocations: `Pairs<T>` (keys and values) is proved
for construction, growth, writes, reads and release (docs/wasm-proof-memory.md, "Records
with several allocations").

**Capabilities** (docs/wasm-capabilities.md, docs/wasm-files.md). Authority enters only
through `main`'s parameters, granted by the run:

| Capability | Grant | What it can do |
|---|---|---|
| `Console<Write>`, `Console<Read>` | `--output`, `--input` | print, read input |
| `Dir`, `Dir<Read>`, `Dir<Write>` | `--dir`, `--write-dir`, `--dir-rights` | one subtree; `dir("sub")` narrows; `rename` stays inside |
| `File<Read>`, `File<Write>` | `--file`, `--write-file` | one file; `File<Write>` is linear |
| `Clock`, `Rand`, `Env` | `--clock`, `--rand`, `--env=NAME` | time, randomness, granted variables only |
| `Net` → `Socket` | `--net=HOST:PORT,...` | dial exactly the granted endpoints; `only` narrows |
| `Listener` → `Socket` | `--listen=HOST:PORT` | accept on one address, nothing else |
| `Exec` → `Run` | `--exec=DIR:name,...` | run granted programs, no shell, empty environment, bounded time |
| `SecretStore` → `Secret<Reveal>` / `Secret<Seal>` | `--secret=NAME`, `--secret-seal=NAME` | read a secret, or sign with it by handle |
| `Allocator` | `--allocator` | heap memory |
| a library's `grantable capability` | `--grant=Type.field=VALUE` | policy data only, never host authority |

Rights narrow and never widen ("a Secret<Seal> is not a Secret<Reveal>"). Libraries
define their own: `capability ConfigDir from Dir<Read>`, or a `capability Table:` block
carrying policy beside a `Net`. `pure fn` is checked to hold no capability.
`witchy-two wasm-caps` reports every reachable function's authority and the program's
total (`--json` for tools); `wasm-caps-diff OLD NEW` fails when a new version holds new
authority. A library's `grantable capability` (policy data, never host authority) is
granted by the run and reported as a user capability. `wasm-grants PROGRAM DOC.toml`
checks a grant document against `main` and prints the engine's flags.
`programs/fileserver.wy` serves one directory over one listening address, and its
footprint shows the request parser can touch only the connection.

**Modules** (docs/wasm-modules.md). Files import files and standard modules by name.
Functions, types, traits and constants are private unless `pub`; functions, types and
generators are per file, so two files may each have a `helper` or a `pub type Entry`
(named `module.Entry` where it is ambiguous); `module.function(...)`, `module.Type` and
`from module import T` name what an imported module offers, and an unqualified call that
could mean two modules' functions is refused.

**Language.** Methods, generics with trait bounds, sums with per-type variant names
(`Right.Io(5)` when the context does not say), records, sealed types with invariants,
`?`, one-line `if`, typed refutable `let`, `for` over containers, `match` with nested
patterns, module constants, generators (`gen fn` / `yield`; docs/wasm-generators.md) and
closures (`fn(n: U64) -> U64: n + by`, passed where `fn(U64) -> U64` is expected, or
returned; docs/wasm-closures.md). A closure may take over a capability and be lent as a
callback, and `wasm-caps` reports the authority where the callback is called. `import
query` gives `Vec` `map`, `filter`, `count_where`, `any`, `all` and lending versions.

**Slices and references.** `&[T]` is a built-in borrowed run of elements, independent of
its container: `a.slice()` (fixed arrays), `v.as_slice()` (a Vec, through the proved
`memory.slice_unchecked`), `text.as_bytes()`; `len`, `at` (a Result), `s[i]`, `part`,
`for item in s`; slices may be parameters, results, record fields and generic
(docs/design-slices.md). A `&` or `&mut` may point at a record that holds references, with
its reference fields frozen behind `&mut` (docs/design-references-to-views.md); closures
capture shared references and slices; generators take them and `yield` inside `for item in
container`. Module constants are per file and may be qualified (`limits.LIMIT`).

**Text and views.** `"total ${t}"` is a value (a format, docs/design-format.md): `console.print`
writes it with no allocator, `String.push_format` appends it with an explicit one; nothing in
the compiler knows those names. Borrowed ranges are library records, not primitives: `Span`
(text), and the built-in slice `&[T]` over fixed arrays and Vecs (docs/design-slices.md). A record holding only shared references (a view) may
be a generic type argument, and a shared `&` may point at one, keeping its loans
(docs/design-references-to-views.md, step 1; `&mut` to a view is next). Loans are per field (`&p.left` beside `&mut p.right`, and writing
`b.count` while a reference into `b.items` is held), and a method may borrow only some fields:
`fn bump(self: Self { &mut count, &step })` (docs/wasm-references.md).

**Speed.** A proof-free build takes 14-18 ms per program (release, including process
start and the proof-cache lookup). Programs whose proofs are cached compile in the same
time; a fresh proof of the Vec library takes about 2.2 s of Lean (over the 2 s goal: about
0.7 s is loading Lean's tactic libraries, the rest is 45 goals on one thread).

## What is proved

Each unchecked memory operation's precondition (bounds, initialization, emptiness before
release) and each `ensures` written in source is a theorem checked by the Lean kernel,
with no axioms beyond Lean's own. Controls for each family of proof are refused by Lean
(for `Pairs`: a missing write, a write to the wrong cell, a double initialization, false
`ensures`, releasing an unemptied allocation, growing too little).

## What remains trusted

- The Lean kernel and the installed proof helper (read-only here).
- The allocator's trusted helpers in the runtime (unchanged).
- The compiler's type and ownership checker: references, moves, linearity, and the
  capability rules are checked by the compiler, not proved. An adversarial review found
  one hole here (a reference leaving a loan through a trait with type parameters, a
  use-after-free) and it is fixed with regression fixtures
  (`references/trait-argument-*.refused.wy`); its other ~30 attempts were refused. A
  second round found a generator correctness bug (break/continue in some nested
  statements; fixed, `generators/continue-in-guard.wy`, `break-in-choose.wy`); a third
  round (modules and privacy, raw host operations from a hostile module, generators,
  user-defined capabilities, `wasm-caps` under-reporting) found nothing, and a fourth
  (per-file private types, seal-only secrets) found nothing unsound. A fifth found a
  flag-injection hole in `wasm-grants` (fixed before it reported, plus glob and comma
  cases) and a `wasm-caps` gap for grantable capabilities in generics (now refused as type
  arguments); a sixth (closures) found nothing unsound and two scoping weak spots, fixed. A seventh
  found a returned closure's declared shape unchecked (fixed); an eighth (callbacks that
  hold authority) found nothing unsound and two misplaced error messages, fixed. A ninth
  confirmed request smuggling through a `Fetch` path (fixed just before it reported: paths
  and hosts with spaces or control bytes are refused), a checker crash on `yield` in a
  closure (now refused) and lenient response parsing (tightened). A tenth (shared
  references as closure arguments) found nothing unsound; its one structural point, that
  the call trait was recognized by name, is closed by reserving `WitchyFn<n>`. The one right it
  noted as enforced by the engine rather than the type (a seal-only secret came back
  as a bare `Secret`) is now in the type too: `get` refuses it and `get_sealed` gives
  `Secret<Seal>`. Rounds eleven to thirteen (per-file types, format values, views as type
arguments, per-field loans, view receivers) found one hole: a view receiver could write an
invariant-bearing field without a proof (fixed: such types lend view fields shared only).
The automated security review caught a view that also held an owner being allowed as a copied
type argument (fixed: it must be Copy). Rounds fourteen to twenty-two (references to views,
slices, `slice_unchecked`, closures and generators holding references) found four holes, each
fixed with a regression fixture: `return &s` of a view parameter read a later call's frame;
a slice returned through a concrete wrapper of `as_slice` dropped the Vec's loan; generic
code given `&mut Box<T>` with `T` a view could store a reference the caller never saw; and
(in review) authority was not followed into slice elements.
- The host (tools/wasmtime-host): path resolution (`openat` with `O_NOFOLLOW`), grant
  checks, the exec sandbox (copy, empty environment, process groups), SHA-256/HMAC. An
  independent review of the newest host code found no escape from grants; its cleanup
  findings were fixed and its remaining caveats are listed in docs/wasm-capabilities.md.

## Not yet

- Grantable capabilities with text fields (numbers and Bools today), TLS, public-key
  signing.
- Generators beyond the first version (owners or references kept between steps, `yield`
  in a `for` over a container, type parameters), and async.
- Closures that capture owners or references, or are one of several returned.
- Inferring a generic type from any later use: today the first later method call on the
  binding settles it when its arguments are typed where the binding is made
  (docs/wasm-generic-functions.md); otherwise an annotation supplies it.
- `&mut` view receivers on types with an invariant (needs a proof covering the whole);
  some per-field loan refusals point at the borrow instead of the conflicting use.
- Review finding Q1 in full: the proof models still recognize shapes; today removed the
  "exactly one allocation" restrictions instead of adding families.
