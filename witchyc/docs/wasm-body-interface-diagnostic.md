# Bounded body-interface diagnostic

`wasm-session-body-interface-diagnostic FILE SDK_SHA256` checks and compiles the current source in a persistent Lean process. It returns diagnostic JSON and the computed Wasm digest; it does not publish a Wasm file or a portable admission receipt. Builds without an explicit ready binding keep full SDK validation.
The separate [production build interface](wasm-production-build.md) publishes checked
Wasm under the explicit selected-generation policy.

Build the helper with the existing builder's explicit `--body-interface` flag. Supply an existing private read-only SDK generation and its full SHA-v1 identity, obtained with `wasm-toolchain-id`. Set `WITCHY_WASM_LEAN_ROOT` and `WITCHY_WASM_NATIVE_HELPER` to those absolute selected paths. See [the helper builder](wasm-proof-session-helper.md) and [selected-generation diagnostic policy](wasm-trusted-generation-diagnostic.md). This mode makes the same operator promise: the selected generation stays unchanged until the session exits. It reports `verified_immutable=false` and `sdk_path_currentness=false`; a read-only copy is not a kernel-sealed immutable installation.

The stdin protocol is unchanged: `check REQUEST_ID EXPECTED_SOURCE_SHA256`, one line per edit. Each request reparses, typechecks and regenerates the complete current proof inventory. The compiler checks the full source identity before and after compilation. A changed source, helper, compiler or context refuses. EOF closes and reaps the owned helper. Any proof or protocol failure ends the session; later requests cannot hide a failure.

For one eligible call-free generic record function body, the compiler installs a separately audited universal theorem in memory. Eligibility uses the existing interpreter's private reached-site evidence. This means a modeled normal path inside a caller definition, not runtime reachability from main. All current body, predecessor, caller and authored/unused obligations remain selected. Only the eligible body's proof may become a fresh kernel-checked application of the installed theorem to the freshly generated current proposition. The current caller and authored/unused proofs remain fresh. A changed body key, multiple bodies or unsupported eligibility uses original fresh proofs before checking; a failed check never falls back.

The key hashes the existing statement, prover, function identity and semantic context; it is a lookup hint. Kernel typechecking against the current proposition is the authority. The same emitter and type/inventory/transitive-axiom auditor serve installation and current modules. Only an audited installation environment is retained. Every current query environment is discarded. No disk theorem receipt, header snapshot, private proof-expression reconstruction or unchecked proof is used.

There are eight total native operations, including LOAD, the optional single INSTALL and STOP. An installed session therefore admits at most five proof checks, with STOP reserved. Limits remain 10 seconds per operation, 2048 MiB runtime memory, 64 KiB modules/output and 32 KiB diagnostics. Known generated unused-binder warnings retain their location and variable name while repeated hint paragraphs are omitted; other warnings, errors and audit records remain complete within the same cap. This is a bounded experiment, not an unlimited warm daemon.

JSON identifies `BODY_INTERFACE_REUSE_DIAGNOSTIC`, `body_interface_reuse`, the selected application, installation cost and per-goal `kernel_typed_body_application` outcomes. It never presents an applied library theorem as a fresh original body proof. Installation/startup costs must be reported separately from edit latency, and amortized session performance must account for the finite check budget. Physical storage mapping, source/VC translation and Wasm emission retain the existing compiler trust boundary.
