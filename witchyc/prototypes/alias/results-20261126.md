# Borrow-derived alias regions for native buffers: results, 2026-11-26

Prototype on `work/alias-regions`, off by default (`WITCHY_NATIVE_ALIAS=1`). Patch:
`native/alias.rs` (the pass and its argument), `native/alias_tests.rs`, hooks in
`native/body.rs` (`alias_root`) and `native/mod.rs`. Base: local main `abb817d9b`.

## What Cranelift did with it

`spread.wy`: a call-free loop that reads `src: &Vec<U64>`, writes `dst: &mut Vec<U64>` and
reads `src` again. Without regions the store to `dst`'s payload (no region) clobbers every
load, so each read of `src` reloads its length, handle, slot generation, block pointer and
prefix: 17 loads an iteration. With regions those come from the loads before the loop and
each read keeps only its element load: 7 loads an iteration. ARM64 for `spread`: 165 to 123
instructions, 22 to 12 loads.

This needed every inlined callee's copy of the heap symbol to be one value: with copies, the
same slot was a different address value and nothing matched. That merge now happens after
inlining for every function, switch or not (`work/inline-global-values`, a23b2d162), and the
table below credits regions with some of what it does; see the correction after the table.

Left: the second `src[i]` element load. The two reads' `Result` arms join before the tag test,
so the first read does not dominate the second; that is jump threading, not alias information.

## Where the pass applies

Over the 70 fixtures that borrow vectors and the benchmarks: 3,088 function reports, 600 with
regions (most of them small library accessors), 713 with no heap access, 1,775 refused. Of the
refusals, 1,544 are parameters the pass does not trust (slices, consoles, allocators, owned
values, sums), then handles not read from a trusted parameter (owned locals on the stack).

## Safety argument (summary of the module comment)

The loan rule: a `&mut` parameter's storage is reached through no other parameter while the
call runs; a `&` parameter's storage is not written while lent. A dense buffer issues no key,
link or weak reference, so its owner field is the only way to it. Only parameters whose type is
a record of plain data and dense buffers of plain data are trusted. Every access is classified
by where its address comes from (record, slot table, header, payload of one parameter's buffer,
or the frame); one access classified otherwise, or a store through `&`, leaves the function
with no regions. A lane joined with a constant filler is read as its address only when the
filler is below 4096, comes from a block that does not dominate the join, nothing variable or
over 4096 is added after the join, and no handle or offset passes through it: on the filler's
arm the access would fault without any region (macOS ARM64 maps nothing below 4 GiB).

## Review

Independent review, four rounds. Round 1: sound with conditions; a compiler crash (a loop
offset taken for a filler). Round 2: unsound (a parameter resolved to a constant: one location
under two regions). Round 3: sound with one condition (an offset through a filler). An
automated security review found a filler flag lost along chained joins. Each was fixed with a
test that fails on the commit before. Round 4, at the tip: sound with conditions:

1. The filler argument is macOS ARM64's zero page; other targets need it again.
2. Accesses keep trapping flags (no `notrap` or `can_move`).
3. Every `&`/`&mut` record parameter comes from call sites the checker saw (future adapters,
   tasks, async, host calls included).
4. Dense buffers stay linear: no keys, links, weak references or copy-on-write sharing.
5. Bounds proofs hold (a wrapped dense index would reach the header) and the header stays 40
   bytes.
6. The heap symbol stays the first global value at offset 0; only calls write the slot table.
7. On each Cranelift upgrade: an untagged store is still a barrier, an untagged load its own
   region.
8. At this tip: the full fixture comparison with the switch on and off, and fuzzing `annotate`
   with random CLIF joins. Not done.

## The strict pass (work/alias-strict, 2026-11-26)

The filler rule and the zero-page argument are gone. A joined address is classified only as
the lane of a tagged join, at a use reached only through a test that the tag equals a value no
other arm gives it (see the module doc). Four review rounds; the first three each found a
miscompile, fixed with a test that failed before the fix:

1. an edge carrying the lane back while retagging it;
2. a lane standing for another join's lane, copied before that lane was tested;
3. a buffer changing owner inside a function (`memory.exchange` of two `&mut Vec`s is plain
   loads and stores): any store that may write a trusted record's owner field now refuses the
   function. This was also in the merged prototype, which tags `prototypes/alias/exchange.wy`'s
   `trade` (42 accesses) and still prints 9 there only because nothing forwarded.

The fourth round found nothing to break and listed the conditions now in the module doc
(owner changes only across calls; regions disjoint between fences for dead-store elimination
too; shared overlaps harmless only while shared stores are refused; record indices checked or
proved).

At the tip: fast suite 599 passed, 0 failed. `spread` gets the prototype's code exactly
(123 instructions and 12 loads against 159 and 22 with the switch off), `bump` 19 accesses with
its read after the store kept, `exchange.wy` refused; all print the same with the switch off and
on. Over the 981 programs that build natively: 3,305 function reports tagged (the prototype:
3,689), the difference all `Vec.reserve_mut`, which rewrites its owner field; the same 24
programs change machine code.

The Vec fuzz program now runs `mirror` (the spread shape) and `settle` (the bump shape) after
every operation; `--expect-regions` fails unless the default build gives both regions. 80 seeds
x 400 operations, 240 runs: all match the model and leave no allocation. Checked and observed
builds reach buffers through runtime calls and get no regions in `mirror`. In this program the
accessors in `settle` and the `index_set` in `mirror` stay calls: native lowering inlines only
bodies lowered earlier, and its order (source leaves, then reverse discovery) puts those
accessors after their callers here. A callee-first lowering order would fix that; it changes
default code generation for every program and is not part of this.

## Tagged loops in the generated test, and the cached qualification (2026-11-26)

`work/alias-fuzz-forwarding` (edfad5df8). The Vec fuzz program's `mirror` and `settle` had kept
their accessors as calls, `settle`'s read could not have been forwarded whatever its region (two
`Result` joins, two addresses), and `control.wy`'s `bump` was inlined into `main`, which gets no
regions, so its tagged copy never ran. Now `main` calls `shadow` first and the two functions use
different accessor wrappers, so each is lowered before its user (native lowering goes in reverse
of first reach; nothing in the compiler's order changed); `settle` reads through `index` twice
(one address); `bump` recurses once a round so it is never inlined. `resolve` follows a parameter
that receives a tagged lane on every edge (an inlined accessor's result passed to the block that
uses it); reviewed sound in a fifth round.

With `--expect-regions` the harness builds the default program with and without regions and
requires `mirror` and `settle` to be tagged and call-free, and `mirror` to have fewer loads:

| function | without regions | with regions |
|---|---|---|
| `mirror` | 218 instructions, 28 loads | 178 instructions, 17 loads |
| `settle` | 130 instructions, 13 loads | 99 instructions, 7 loads |

80 seeds x 400 operations, 240 runs, all match the model. A scratch compiler that put every
store under a region of its own fails 4 of 5 seeds (`settle` prints the value from before its
write) and prints 0 instead of 192 for `bump`.
